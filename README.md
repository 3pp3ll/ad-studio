# استوديو تصميم وتسويق (الإصدار 6)

تطبيق ويب ثابت (HTML + CSS + JavaScript بلا إطار عمل ولا خطوة بناء إلزامية) لكتابة الإعلانات وتوليد صورها وفيديوهاتها، مع لوحة إدارة. يعمل كاملاً بلا خادم، ويمكن ربطه اختيارياً بـ OpenRouter.

## التشغيل بلا خادم

افتح `index.html` بنقرة مزدوجة. لا يحتاج تثبيتاً ولا إنترنت (الخط فقط يُحمَّل من Google Fonts، وبدونه يظهر خط الجهاز).

- البيانات (المستخدمون، الإعلانات، الإعدادات) تُحفظ في `localStorage` تحت المفتاح `adhelper-v1`.
- الصور والفيديوهات والصور المرجعية تُحفظ في IndexedDB (قاعدة `adhelper-media`).
- كل شيء محفوظ في متصفح هذا الجهاز فقط، ولا ينتقل بين الأجهزة.
- بيانات الإصدارات 3 و4 و5 تُرحَّل تلقائياً إلى الإصدار 6 عند أول فتح؛ أي إصدار أقدم يُستبدل ببيانات الأمثلة.

ملف واحد بدل المجلد: `npm run build` ينتج `dist/adhelper.html` وفيه كل شيء.

## النشر على GitHub Pages والتثبيت على الجوال

المجلد كما هو يعمل كموقع ثابت على GitHub Pages: من إعدادات المستودع ← Pages اختر الفرع `main` والمجلد `/ (root)`. الموقع قابل للتثبيت كتطبيق (`manifest.webmanifest` و`sw.js` و`icons/`):

- **آيفون (Safari):** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- **أندرويد (Chrome):** القائمة ⋮ ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية».

بعد كل تحديث للملفات غيّر `VERSION` في `sw.js` حتى يحمّل الجوال النسخة الجديدة.

## الوضع التجريبي (fallback) والوضع الحقيقي

| | بلا ربط (fallback) | مع ربط OpenRouter |
|---|---|---|
| النصوص والصيغ والعناوين والهاشتاقات | قوالب جاهزة داخل `js/ai.js` | يكتبها نموذج النصوص |
| الصورة | ملصق يُرسم محلياً على Canvas | يولّدها نموذج الصور |
| الصورة المرجعية | تصير خلفية الملصق تحت طبقة داكنة | تُرسل للنموذج مع الوصف |
| الفيديو | غير متاح | يولّده نموذج الفيديو |
| اللغات غير العربية | صيغة واحدة مبسّطة لكل لغة | الأسلوب الكامل باللغة المختارة |

إذا فشل طلب حقيقي يرجع التطبيق للقالب أو للملصق، ولا يُخصم من رصيد الصور أو الفيديو إلا بعد نجاح التوليد.

## تفعيل الربط الاختياري

من **لوحة الإدارة ← الإعدادات ← ربط OpenRouter**، بإحدى طريقتين:

**1) مباشر (للتجربة على جهازك فقط).** اترك «رابط API» كما هو (`https://openrouter.ai/api/v1`)، الصق المفتاح، فعّل «استخدام OpenRouter فعلياً»، ثم «اختبار الاتصال». المفتاح هنا محفوظ في المتصفح ويراه كل من يستخدم الجهاز، فلا تستعمل هذه الطريقة في موقع منشور.

**2) عبر البروكسي (للنشر).** انشر `server/worker.js` (الخطوات في الأسفل)، ضع رابط الـ Worker في «رابط API»، واترك حقل المفتاح فارغاً. المفتاح يبقى في Cloudflare ولا يصل للمتصفح.

النماذج الافتراضية قابلة للتعديل من نفس الصفحة:

- النصوص: `google/gemini-2.5-flash`
- الصور: `google/gemini-2.5-flash-image`
- الفيديو: `x-ai/grok-imagine-video`، المدة من 6 إلى 15 ثانية يختارها المستخدم، المسار `/videos`

## المرفقات وتصميم الديكور

في صفحة «توليد صورة» أو «توليد فيديو» اضغط **إرفاق صور أو فيديو** واختر حتى 6 ملفات، ويمكنك كتابة وصف لها.

- الصور تُصغَّر إلى 1600 بكسل كحد أقصى؛ الفيديو يُحفظ كما هو.
- المرفقات تُحسب من مساحة التخزين فقط، وتُحفظ مع الإعلان وتظهر في المكتبة بتسمية «مرجع».
- مع الربط تُرسل للنموذج مع الوصف. المرفق الفيديو يُرسل كصورة (إطاره الأول)، لأن نقطة الفيديو في OpenRouter تقبل صوراً لا مقاطع.
- بلا ربط يصير أول مرفق خلفية للملصق التجريبي.

**تصميم ديكور:** عند اختيار نوع المنتج «ديكور» أو «أثاث» مع وجود مرفقات يتحول زر التوليد إلى «تصميم ديكور (بناءً على المرفقات)». الطلب عندها: تأثيث المكان الظاهر في المرفقات مع الحفاظ على أبعاده وزاوية تصويره. في الفيديو يتم ذلك على خطوتين: تصميم صورة للمكان بعد تأثيثه (تُحفظ كصورة الإعلان وتُخصم صورة واحدة)، ثم توليد مقطع يبدأ منها. الناتج مقطع مولَّد يبدأ من لقطتك، وليس مقطعك الأصلي نفسه بعد التعديل.

## هوية الشركة

الشعار والأسماء والألوان ومحتوى التذييل وصفحات «عن الشركة» والشروط والخصوصية كلها تُعدَّل من «لوحة الإدارة ← الإعدادات ← بيانات الشركة» و«ألوان الواجهة»، وتُحفظ في `S.settings.company` و`S.settings.brand`. لا توجد بيانات شركة مكتوبة في الكود غير الاسم والشعار الافتراضيين.

- الشعار الافتراضي في `js/brand.js` كصورة مضمّنة (data URL)، ويُستخدم للترويسة والتذييل وأيقونة المتصفح. يُستبدل برفع صورة أو بكود SVG أو برابط https.
- كل حقل فارغ لا يظهر: السجل التجاري، الرقم الضريبي، البريد، الهاتف، العنوان، الروابط.
- رابط «عن الشركة» يظهر في التذييل عند كتابة الشعار النصي للشركة. رابطا الشروط والخصوصية يظهران عند كتابة نصّيهما.

## إعدادات الحساب والمشاركة

صفحة «إعدادات الحساب» فيها بيانات المستخدم، واختيار المظهر (تلقائي، فاتح، داكن) كأيقونات، وحسابات التواصل الاجتماعي. اضغط أيقونة المنصة والصق رابط حسابك، أو أيقونة الإضافة لحساب غير موجود في القائمة.

المنصات تظهر بأسمائها إلى أن تُضاف شعاراتها. الشعارات الرسمية غير مرفقة مع المشروع: خذها من صفحة العلامة التجارية لكل منصة، ثم ارفعها من «لوحة الإدارة ← الإعدادات ← أيقونات المنصات»، أو ضعها في مجلد `assets/social/` باسم المنصة (`instagram.svg`، `twitter.svg`، `facebook.svg`، `tiktok.svg`، `whatsapp.svg`، `youtube.svg`، `snap.svg`) فتظهر تلقائياً لكل الزوار.

زر «مشاركة» في صفحة إنشاء الإعلان وفي المكتبة ينسخ النص والهاشتاقات ثم يعرض رابطاً يفتح المنصة. X وواتساب يفتحان منشوراً جديداً والنص مكتوب فيه؛ باقي المنصات لا تتيح ذلك من رابط، فيفتح حسابك وتلصق النص. الصور والفيديو لا تنتقل تلقائياً في أي منصة. النشر التلقائي الكامل يحتاج ربط واجهات المنصات من الخادم.

زر الفرشاة في أعلى صفحات الإنشاء ينظّف الشاشة لإعلان جديد؛ ما حُفظ يبقى في المكتبة.

## التصدير والفواتير

زر «مشاركة» بجانب كل إعلان في المكتبة يفتح قائمة: النشر على المنصة، أو تصدير كامل المحتوى كملف مضغوط (النص وكل الصور والفيديو) أو كملف PowerPoint (النص والصور، والفيديو يُذكر بالاسم). البريد يحمل النص فقط، ولـ Google Drive ينزَّل الملف المضغوط ثم يُرفع يدوياً؛ الإرسال المباشر لهما يحتاج ربطاً من الخادم. الملفات تُبنى داخل المتصفح (`js/export.js`).

الإضافات في صفحة الباقات يحدد المستخدم كميتها (مثل المساحة وثواني الفيديو) ويرى المبلغ النهائي قبل الدفع. من لوحة الإدارة يُحدَّد لكل إضافة التسعير: «مجموعة ثابتة» أو «بالوحدة». بعد الدفع تصدر فاتورة تُعرض وتُنزَّل كملف HTML، ومكتوب عليها أنها عملية تجريبية ما دام الدفع محاكاة.

## المشاهد (مونتاج بسيط)

صفحة «المشاهد» ترتّب صوراً ومقاطع في إعلان واحد مدته من 6 إلى 15 ثانية: أضف ملفات من جهازك أو صورة الإعلان وفيديوه، حدّد ثواني كل مشهد والنص الظاهر عليه، ثم شغّل المعاينة. حقل «النص الحواري» يُحفظ مع الإعلان ويُرسل لنموذج الفيديو عند التوليد.

المعاينة تعمل داخل المتصفح فقط. تصدير الإعلان كملف MP4 واحد يحتاج خادماً (ffmpeg) وليس ضمن هذه النسخة.

## الباقات والإضافات

من «إدارة الباقات» تُعدَّل أسماء الباقات وأسعارها وكل حصصها (إعلانات، صور، تحليلات، ثواني فيديو، مساحة)، وتُضاف باقات جديدة. رصيد الفيديو يُحسب بالثواني لا بعدد المقاطع.

في الصفحة نفسها جدول «إضافات للباقة»: عناصر يشتريها المستخدم فوق باقته (مساحة، صور، ثواني فيديو، إعلانات، تحليلات) باسم ونوع وكمية وسعر تحددها أنت. الشراء محاكاة مثل الاشتراك.

## دخول الإداري

لا توجد صفحة دخول منفصلة للإدارة. الإداري مستخدم عادي عليه `isAdmin` و`adminRole`، ويدخل من صفحة تسجيل الدخول نفسها ثم يظهر له زر **لوحة الإدارة** في الشريط العلوي.

حسابات تجريبية (كلمة المرور لكليهما `demo-pass`):

- `demo@example.com` مستخدم عادي
- `owner@example.com` إداري بدور Super Admin

الأدوار: Super Admin، Admin، Support، Finance، AI Monitor. كل دور يرى صفحات محددة، ويمكن منح صفحات إضافية لكل حساب من «إدارة المستخدمين» أو «الإعدادات ← حسابات الإدارة». آخر Super Admin نشط لا يمكن تخفيضه أو إيقافه أو حذفه.

الحسابات المنشأة من صفحة «إنشاء حساب» تُحفظ كلمة مرورها كبصمة SHA-256 مع ملح، لا كنص.

## لغة الواجهة والمظهر

زرّان في الشريط العلوي: تبديل الواجهة بين العربية والإنجليزية (يغيّر الاتجاه أيضاً)، وتبديل المظهر (تلقائي، فاتح، داكن). الاختياران يُحفظان في الإعدادات. لغة الإعلان نفسه تُختار من صفحة «إنشاء إعلان» وهي مستقلة عن لغة الواجهة.

كل نصوص الواجهة في `js/i18n.js` بصيغة `مفتاح: ['عربي', 'English']`، وتُستدعى بـ `t('مفتاح')`. بيانات الأمثلة (أسماء المستخدمين، سجل الأخطاء، الاقتراحات) تبقى بالعربية لأنها بيانات وليست واجهة.

## هيكل المشروع

```
adhelper/
├── index.html            نقطة الدخول
├── css/style.css         كل الأنماط والألوان (فاتح/داكن)
├── js/
│   ├── i18n.js           قاموس الواجهة عربي/إنجليزي ودالة t()
│   ├── brand.js          الشعار الافتراضي كصورة مضمّنة
│   ├── state.js          الثوابت، seed، الترحيل، الحفظ في localStorage
│   ├── storage.js        IndexedDB للصور والفيديو والمرفقات
│   ├── media.js          ملصق Canvas وروابط الصور وتصغير المرفق
│   ├── ai.js             القوالب (fallback) واستدعاءات OpenRouter
│   ├── views-user.js     صفحات المستخدم (ومنها المشاهد)
│   ├── views-admin.js    صفحات الإدارة
│   ├── export.js         تصدير ZIP و PowerPoint والفواتير
│   └── app.js            الإقلاع، التنقل، الأفعال، الأحداث
├── server/
│   ├── worker.js         بروكسي Cloudflare Worker يخفي المفتاح
│   └── wrangler.toml
├── build.js              يدمج المشروع في dist/adhelper.html
├── .env.example
└── package.json
```

الملفات سكربتات عادية (ليست ES modules) حتى يعمل `index.html` بالفتح المباشر من القرص.

## السكربتات

```
npm run dev            خادم محلي على المنفذ 8080
npm run build          ينتج dist/adhelper.html (ملف واحد)
npm run worker:dev     يشغّل البروكسي محلياً
npm run worker:secret  يحفظ مفتاح OpenRouter في Cloudflare
npm run deploy         ينشر البروكسي
```

## نشر البروكسي

1. أنشئ حساب Cloudflare وسجّل الدخول: `npx wrangler login`.
2. احفظ المفتاح كسرّ: `npm run worker:secret` ثم الصق المفتاح.
3. في `server/wrangler.toml` غيّر `ALLOWED_ORIGIN` من `*` إلى رابط موقعك.
4. `npm run deploy`، وانسخ الرابط الناتج إلى «رابط API» في الإعدادات.

للتجربة المحلية: انسخ `.env.example` إلى `server/.dev.vars` واكتب المفتاح، ثم `npm run worker:dev`.

## حدود يجب معرفتها قبل النشر

- **بلا خادم، كل زائر له نسخته الخاصة.** إذا رفعت الصفحة على سيرفر وفتحها أصدقاؤك، فكل واحد يرى بيانات متصفحه فقط: حساباتهم لا تظهر في لوحة إدارتك، وتعديلاتك على الباقات والأسعار لا تصلهم. التجربة المشتركة تحتاج قاعدة بيانات في الخادم.

- **البروكسي يخفي المفتاح فقط.** كل من يعرف رابطه يستطيع استهلاك رصيدك؛ `ALLOWED_ORIGIN` يمنع المواقع الأخرى من المتصفح لكنه لا يمنع الطلبات المباشرة. الحماية الفعلية تحتاج تسجيل دخول في الخادم وحصة لكل مستخدم.
- **تسجيل الدخول والصلاحيات والحصص والمساحة تُطبَّق في المتصفح**، فهي لا تحمي من مستخدم يعدّل بيانات متصفحه. في التطبيق النهائي تنتقل إلى الخادم (Supabase في خطة البناء).
- **الدفع محاكاة**، ولا يوجد ربط Stripe.
- **طلبات OpenRouter مكتوبة حسب توثيقهم ومختبرة بخادم وهمي**، لا بمفتاح حقيقي. غير المؤكد تحديداً: قبول نقطة الفيديو لصورة مرجعية بصيغة data URL (أمثلة التوثيق تستخدم روابط https).
